# 多模态「脚本—分镜—视频」流水线产品（SaaS + 桌面端）设计说明

**状态**：待你审阅后定稿  
**日期**：2026-05-07  

---

## 1. 背景与目标

### 1.1 产品目标

交付一款可安装的**桌面客户端**，支持用户输入 **自然语言** 与 **参考/源视频**，通过 **多模态文本模型** 生成完整 **视频脚本 + 故事版（分镜结构化）**；再由 **生图模型** 按分镜生成静态关键帧/分镜图；由 **视频生成模型** 结合分镜图与故事版中的视频提示词生成 **视频片段**；最后 **拼接为成片**。

### 1.2 已确认的约束与取舍

| 项 | 选择 | 说明 |
|----|------|------|
| 输入 | 文本 + 视频 | 双链路均需在一期纳入产品范围（可先实现「最小可用切片」再并行扩展） |
| 平台并发 | ~100 条流水线任务（全平台合计） | 需要可水平扩展的 **任务队列 + Worker**，以及 **Provider 级限流与退避** |
| 模型 API | [https://ai.t8star.cn/](https://ai.t8star.cn/) | 网关需按对方 **鉴权、计费单位、异步轮询/回调** 等规范封装；具体端点以接入文档为准 |
| 调用路径 | **B：经自有后端代发** | 桌面端 **不持有** 平台侧 t8star 密钥；由后端 **密钥池** 转发请求，并与 **会员/积分** 联动 |
| 自有云职责 | 账号（注册登录）、会员、积分及核心编排 | 不包含把全部推理算力自建在一期范围（推理走 t8star） |
| 媒体持久化 | **B：以外部 URL / 任务 ID 为主** | 业务库以 **元数据 + 外部引用** 为主；需接受 **外链过期、不可复现导出** 等产品与合规风险 |

### 1.3 非目标（第一期明确不做或显式降级）

- 不做「无限画板」的剪辑级全功能（多轨时间线专业剪辑）作为一期必达；画板优先承载 **分镜卡片、节点流水线、审阅批注**。
- 不把「100 并发」等价于「100 路同步长视频满血生成」；并发指 **可调度任务数**，实际吞吐受 t8star 配额、单任务时长、 Worker 数限制。
- 不在一期建设完整「私有云交付包」；但若架构分层清晰，可为二期私有化预留接口与配置抽象。

## 2. 总体架构（推荐方案）

### 2.1 逻辑分层

1. **桌面端（Electron + Web UI）**  
   - 负责：项目/任务创建、素材上传（若走直传需后端签发）、画布呈现、进度订阅、成片下载（跳转外链或代理流式下载）。
   - 禁止：嵌入平台密钥、直连 t8star（除非二期「高级用户自备 key」等产品变更）。

2. **BFF / API 网关（HTTPS）**  
   - JWT / Session、鉴权中间件  
   - 积分预检与扣减（建议使用 **reserve → settle / release** 两阶段，避免长跑任务失败仍扣款）  
   - 租户/用户级 **限流** 与全局 **出站 QPS** 协调（Redis 令牌桶或漏桶）  
   - 审计日志（每次模型调用：user_id、project_id、job_id、模型名、计价、latency、HTTP 状态）

3. **编排服务 Orchestrator（可与 API 同进程或拆分）**  
   - 将一条「成片任务」编译为 **有向无环图（DAG）**：`storyboard → image × N → video × N → concat`（具体节点依 t8star 能力与产品策略可调）。  
   - 把节点推入队列，监听状态机迁移。

4. **异步 Worker（可水平扩容）**  
   - 消费队列任务，调用 **Provider Adapter**：`t8star`  
   - 支持 **异步轮询**、t8star 若在文档中支持 **Webhook** 则优先 Webhook + 超时兜底轮询。

5. **数据存储**  
   - **PostgreSQL**：用户、会员、积分流水、项目、任务、DAG 快照、每一步输出摘要（外链、mime、checksum 可选、t8star task id）。  
   - **Redis**：队列后端（推荐 **BullMQ**）、分布式锁（同 job 단계互斥）、限流计数器。

6. **（可选）短期临时存储 / 中转**  
   - 若成片 **拼接（concat）** 无法由 t8star 一站式完成：Worker **临时下载** 片段至 ** ephemeral 磁盘或内存**，用 **ffmpeg** 拼接后立即删除；**不落盘长期对象存储**仍符合当前「B 策略」，但须在隐私政策与数据中台说明「短时处理必要性」。

### 2.2 备选方案简述（你已选定主方案）

- **备选 1：用户自备 key（A 模式）**：实现快、法务轻，但无法用积分强约束、密钥泄露面广，已与当前目标不符。  
- **备选 2：全量自建媒体存储（A）**：可控与可回放最好，成本高；你已选以外链为主，故一期不采用作为主路径。

**推荐保持不变**：你已选的 **后端代发 + 外链为主** 组合成本最低；用「临时 ffmpeg + 不落长期存储」兜底合成缺口。

## 3. 核心数据模型（概要）

以下为逻辑实体，迁移时可拆表。

- **User**：账号基础信息  
- **Membership**：套餐、到期时间  
- **CreditAccount / Ledger**：积分余额与流水（扣减冻结、解冻、回补）  
- **Project**：画板所属的「项目容器」  
- **Asset**：可选；若完全不落库文件，则用 `source_type`（upload_url | external_ref）指向外部  
- **RenderJob**：一次「从源头到成片」的主任务，`status`、`dag_version`、`priority`  
- **RenderStep**：DAG 节点实例，`kind` ∈ {analyze_text, analyze_video, storyboard_llm, image_gen, video_gen, concat}, `input_ref`、`output_ref`（JSON）、`retry_count`、`idempotency_key`  
- **ProviderCall**：单次对 t8star 的请求/响应摘要（便于对账与排障）

**幂等**：`RenderJob` 维度或 `RenderStep` 维度带 `idempotency_key`，防止队列重试导致重复计费。

## 4. 流水线与并发

### 4.1 任务状态机（示例）

`queued → running → awaiting_external → composing → succeeded | failed | canceled`

其中 `awaiting_external` 用于异步模型任务。

### 4.2 并发 100 的工程含义

- **队列深度** 可容纳 ≥100 incoming jobs；**Worker 并发** 通过环境变量控制（如每实例 5–20），多实例堆叠至总吞吐与 t8star 配额匹配。  
- **全局限流**：全局 token 桶限制「对 t8star 的并发 HTTP / 每秒请求」，避免触发对方封禁并控制成本。  
- **公平性**（二期可增强）：每用户最大并行 job 数，防止单用户占满 100。

### 4.3 失败与重试

- **可重试**：网络超时、429、对方明确 `retry_after`  
- **不可重试**：鉴权失败、内容策略拒绝、参数错误（进入 `failed` 并 **release 冻结积分**）  
- **人工介入**：画布上可对某一 `RenderStep`「重生成 / 改写提示词」，产生 **子 DAG** 或新版本 `RenderJob`。

## 5. 安全与合规要点

- 平台密钥仅存在于 **服务端机密存储**（K8s Secret / 云服务 KMS），按环境轮换。  
- 桌面端到后端：**TLS**，**JWT 短期 Access + Refresh** 或设备绑定策略。  
- **外链留存**：需在用户协议说明成片/中间产物链接可能失效；可提供「有效期内重新打包下载」二期能力（若迁到自有存储则升级为策略 A）。

## 7. 测试策略（概要）

- **契约测试**：Mock t8star 适配器响应（同步、异步、429、超时）。  
- **编排单元测试**：DAG 编译与状态迁移。

- **负载测试**：仿真 100 入队 tasks（可先 stub provider）验证队列与 DB 不写爆。

## 8. 开放问题（需在实现计划中落地或回填）

以下不阻塞你做总体评审，但在开发前必须从 t8star 文档或商务侧确认：

1. **异步任务语义**：Webhook 是否存在、最长轮询时间、产物 URL 生命周期。  
2. **计费维度**：按 token、按时长、按次；是否区分图片/视频。  
3. **视频理解与生成**：一期是否同一种「多模态模型」链路完成，还是需要多个 endpoint。  
4. **拼接**：t8star 是否提供「多段合成」API；若没有，确认 Worker 侧 **ffmpeg 临时合成**流程与超时资源上限。

## 9. 验收标准（一期）

1. 用户可 **注册/登录**，可见 **积分/会员**状态；创建项目并在画布中看到任务节点状态流转。  
2. **文本输入** 可走通：故事版 → ≥1 分镜图 → ≥1 视频片段 →（拼接或等价）成片可下载或可打开外链。  
3. **视频输入** 可走通等价链路（分析/重写故事版的路径与文本不同，但对用户透明为同一类「成片任务」）。  
4. 在压测环境可稳定承载 **≥100** 个「已入队且处于非终态」的任务调度（Worker 可调参），且全局限流与账务不出现异常负余额。
